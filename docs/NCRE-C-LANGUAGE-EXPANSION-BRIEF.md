# NCRE 二级 C 语言题库扩充 · 任务说明书

> **使用者**：这份文档是写给"负责出题的 AI"的。它自包含，不需要任何额外背景。
> **目标**：为「全国计算机等级考试二级 C 语言程序设计」题库新增 **290 道单项选择题**，使总题量从 **310 → 600**。
> **验收方**：题目的最终入库由仓库维护者完成；你只需要交付一个符合本说明格式的 `questions.json`。

## 0. 先读这一段（最重要的四条）

1. **只出单项选择题**。官方大纲的客观题部分**只有单项选择题**，没有多选题、没有判断题。出成多选或判断一律作废。
2. **每题恰好 4 个选项、恰好 1 个正确答案**，另外 3 个必须**确实错误**。
3. **知识点名称必须逐字照抄第 5 节的目录**（包括空格、"、"、"与"等），一个字都不能改，否则无法入库。
4. **不要照抄任何真题、教辅、网络题库的原文**。这是原创仿真题，题干与选项必须自己设计。

## 2. 输出格式（严格）

交付一个 **UTF-8 无 BOM** 的 JSON 文件，顶层是**数组**，每个元素是一道题，**字段恰好 11 个，不多不少**：

```json
{
  "id": "ncre-cx1-ptr-address-001",
  "type": "single_choice",
  "question": "题干",
  "options": { "A": "...", "B": "...", "C": "...", "D": "..." },
  "answer": ["B"],
  "analysis": "解析",
  "chapter": "指针",
  "knowledgeSection": "指针基础",
  "knowledgePoint": "地址与指针变量",
  "difficulty": "easy",
  "tags": ["指针", "间址运算符"]
}
```

字段规则：

| 字段 | 要求 |
|---|---|
| `id` | **全局唯一**，小写 slug，本批**必须以 `ncre-cx1-` 开头**（第二轮用 `ncre-cx2-`，依此类推）。格式建议 `ncre-cx1-<知识点缩写>-<三位序号>` |
| `type` | **固定字符串 `single_choice`**，不得出现其它值 |
| `question` | 题干。必须自包含，**禁止**出现"如下图""见下表"这类依赖外部图片的表述 |
| `options` | **正好 4 个键** `A`/`B`/`C`/`D`。**忽略大小写后四项文本不能重复**（系统会把选项转小写后比对，`AB3C` 与 `AB3c` 会被判重复） |
| `answer` | **恰好一个字母**的数组，如 `["C"]`。不能是 `["A","B"]`，也不能是字符串 `"C"` |
| `analysis` | ≥12 字符。**必须写出推理过程，并逐项说明另外三个选项为什么不对**。**不要用"选项 A""A 项"这种字母指代**，要用内容描述（如"把 sizeof 当成元素个数"） |
| `chapter` | 必须是第 5 节 12 个模块名之一，**逐字一致** |
| `knowledgeSection` | 必须是该模块下的二级分类名，**逐字一致** |
| `knowledgePoint` | 必须是该二级分类下的知识点名，**逐字一致** |
| `difficulty` | 只能是 `easy` / `medium` / `hard` |
| `tags` | 1–8 个字符串，便于检索 |

**不要**输出 `provenance`、`source`、`certificates` 等字段——那些由入库流程自动生成。

## 6. 质量红线

### 6.1 绝对禁止

1. **禁止多选题、判断题**——只出单选。
2. **禁止两个正确选项**。每题出完后必须回读四个选项，确认另外三个**确实错**。
3. **禁止依赖未定义行为或未指定求值顺序**，例如：
   - `i = i++ + ++i;`
   - `printf("%d %d", f(), f());`（`f` 有副作用）
   - 对**负数右移**
   - 修改字符串常量 `s[0]='H'`（这类可以出"判断是否合法"，但**不能**要求预测其结果）
   - 数组越界写
4. **禁止选项重复**（忽略大小写）。
5. **禁止解析用字母指代选项**（"选项 A""B 项"）。
6. **禁止解析提到不存在的选项**（换过选项后必须同步改解析）。
7. **禁止题干依赖图片/表格**（"如下图""见下表"）。
8. **禁止照抄真题/教辅原文**。

### 6.2 必须做到

1. **干扰项要"可导出"**：每个错误选项都必须对应一种**具体的误解**，而且按那种误解**真的能算出该选项的数值**。
   > 这是本库复核时抓出最多问题的地方：曾有 3 道题的干扰项数值（24、32、10）无论如何都推不出来，被判定为弱干扰项。出完数值型选项后，**请自己按解析说的错误思路算一遍**，看等不等于该选项。
2. **技术表述必须准确**。本库真实踩过的坑（务必规避）：
   - ❌ 把「结合性」与「优先级」混为一谈。`a *= b + 3` 等价于 `a = a*(b+3)`，原因是**复合赋值优先级低于加法**，不是"结合方向从右到左"。
   - ❌ 说 `scanf` 格式串里的空格"必须原样输入"。实际**空白字符是空白指示符，可匹配 0 个或多个空白**。
   - ❌ 说"复合语句右花括号后不能加分号"。实际多写一个只是紧跟的**空语句**，合法；错的是说"**必须**加"。
   - ❌ 说数组补零"与静态存储期有关"。实际带初始化列表的聚合，未显式初始化的元素**一律补零，与存储期无关**。
   - ❌ 说"返回已结束生存期的局部变量的地址"和"返回函数内局部数组的指针"是两种不同错误——它们是**同一类**悬空指针错误，不能放在同一道单选里当两个选项。
3. **依赖实现取值的题，必须把前提写进题干**（如 `sizeof`、各类型字节数、对齐、指针宽度）。
   ✅ 正确写法："在 32 位环境中 int 占 4 个字节，则 `int a[2][3]` 占多少字节？"
   ❌ 错误写法：只说"在 Microsoft Visual C++ 2010 环境中"就要求算 `sizeof`——因为外部文档未必能逐版本佐证该取值。
4. **代码题必须语法正确**，并且**自己逐轮手工推导**出输出再写答案，不能凭感觉。
5. **一题一个考点**：一题只考一个知识点（见第 5 节），不要一题同时考三四个概念。
6. **同一知识点的题要换角度**：不要用同一道题换数字。可用角度举例——概念辨析、执行跟踪、边界条件、反向推理、错因诊断、代码改错。

import fs from "node:fs";
const q = JSON.parse(fs.readFileSync("questions.json", "utf8"));

for (const [k, v] of out) console.log(`${k}: ${v}`);

console.log("模块分布:", JSON.stringify(byChapter));
const byAns = {};

console.log("答案位置:", JSON.stringify(byAns));
const byDiff = {};

console.log("难度分布:", JSON.stringify(byDiff));
