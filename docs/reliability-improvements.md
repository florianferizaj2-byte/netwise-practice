# 可靠性优化 · 2026-10-02

这次更新处理自动化验证、AI 任务容量、登录保护、考试答案保存和电脑网页加载，不修改题干、选项、答案或题目来源。

## 学习者能看到的变化

- 考试明确显示保存状态。网络失败时保留当前浏览器的待保存答案，可手动重试，恢复联网后也会尝试同步。
- 同一账号在其他设备打开考试页，可以从未完成考试记录继续。恢复时读取服务器最新答案；两端同时作答发生冲突时，选择使用已同步答案或合并本机尚未同步的作答。
- 登录、注册过于频繁时显示等待时间。密码计算在后台线程执行，减少对其他页面请求的影响。
- 不同账号可以同时使用 AI。同一账号一次处理一个任务，超时或生成轮数达到上限会结束失败任务并按原有额度规则返还额度。
- 练习、考试、社区、VIP 和管理等页面按需加载，并提供加载中和加载失败提示。

考试的本机备份按账号与证书隔离，仅用于恢复尚未保存的选择。清理浏览器数据或禁止本机存储会影响本机备份；已经同步的答案仍可从服务器恢复。考试到时以截止前服务器保存的答案计分，重复交卷不会重复计入学习记录。

## 服务端默认参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `AI_MAX_CONCURRENT_TASKS` | 3 | 同时执行的 AI 任务上限 |
| `AI_MAX_QUEUED_TASKS` | 40 | 即时 AI 请求的等待队列上限 |
| `AI_QUEUE_WAIT_MS` | 30000 | 即时请求最多排队 30 秒 |
| `AI_TASK_TIMEOUT_MS` | 180000 | 一个 AI 任务执行最多 3 分钟 |
| `AI_GENERATION_MAX_ROUNDS` | 5 | 扩充题库、后台生成题组的补生成轮数上限 |
| `AUTH_RATE_WINDOW_MS` | 900000 | 登录与注册计数窗口，默认 15 分钟 |
| `AUTH_LOGIN_IP_LIMIT` | 60 | 每个 IP 的登录类请求次数 |
| `AUTH_LOGIN_ACCOUNT_LIMIT` | 20 | 每个账号的密码登录请求次数 |
| `AUTH_REGISTER_IP_LIMIT` | 10 | 每个 IP 的注册请求次数 |

登录类请求包括密码登录、微信绑定和小程序登录；普通注册与微信注册共用注册限制。计数保存在 SQLite 中，重启服务不会清空当前窗口；限制触发时返回 HTTP 429 和 `Retry-After`。反向代理继续使用项目现有 `TRUST_PROXY` 配置，应匹配实际代理层数。

AI 上限针对单个服务进程。持久化后台出题队列沿用原有账号任务和额度记录，调度时跳过正在执行任务的账号；即时请求只在开始执行时扣额度。单次上游请求还受原有 45 秒超时约束。该版本面向现有单进程部署。

## 发布前检查与更新

1. 安装根目录与 `mobile/` 的锁定依赖，并安装 Playwright Chromium 和 WebKit。
2. 运行 `npm run verify`。检查包括题库结构、移动端类型、单元与接口测试、两套网页构建、浏览器真实流程。
3. 沿用现有部署方式更新 `server/` 和完整 `dist/`（包含 `dist/app/`），保留服务器数据库、上传文件、`.env` 和 AI 主密钥。
4. 重启后，新增的限流表会自动创建；已有考试从答案版本 0 开始。旧客户端仍可保存和交卷，新网页和更新后的移动端使用版本号检查冲突。

Android v0.3.9 包含考试冲突处理，并沿用现有正式签名。发布版本与下载入口已更新；安装包和编译后的服务器更新包见 [v0.3.9 发布说明](release-v0.3.9.md)。新增服务端能力与站点下载提示需要维护者部署更新包后生效；GitHub 工作流只执行检查，不会自动部署。

浏览器回归使用隔离的临时账号、数据库和 AI 测试桩。电脑端失败时查看 `test-output/e2e-failure.png` 与 `test-output/e2e-failure.txt`，移动端失败记录位于 `test-output/apple-web/`；持续集成会将失败截图和页面文本保存为附件。
