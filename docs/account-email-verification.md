# 注册邮箱验证与密码恢复

## 当前交付状态

2026-10-16 按用户最新要求，邮箱发信、验证注册、邮箱绑定和邮箱找回的代码保留，默认关闭；本地 `.env` 和 `.env.example` 均设置 `AUTH_EMAIL_VERIFICATION_ENABLED=0`。Web、App 和小程序读取服务端开关，关闭时不显示邮箱验证码/邮箱找回入口，普通账号密码注册、登录及登录后改密正常保留。已保存的邮箱和验证数据不删除。

即使填好了 SMTP 配置，也不会自动启用。关闭时邮件发送、邮箱绑定和邮箱重置接口返回 `EMAIL_FEATURE_DISABLED`，不建立 SMTP 连接、不发送邮件，也不把用户填写的地址记为已验证。开启后，普通/微信新注册才要求验证邮箱；已有账号和微信绑定登录不变。前端读取开关失败时仍允许登录，但暂停新注册并提供重试，避免错误跳过启用状态下的验证。

当前未部署生产服务器，也未发布新的 APK；手机网页验证不能替代 App 真机验收。

## 以后需要时再启用

当前无需准备发件服务。以下配置仅作为保留功能的启用说明。

准备一个由自己管理的专用发件邮箱，并在该邮箱服务商处开通 SMTP 或事务邮件发送。取得服务商给出的 SMTP 服务器地址、TLS 端口、登录账号、授权密码和允许使用的发件地址。

SMTP 授权密码只填入服务器的环境变量或私有 `.env`，不要发送到聊天、放到前端/小程序配置或提交到仓库。请依照服务商的官方说明完成开通；此实现不限定邮箱服务商。

服务器配置示例（全部占位符须替换）：

```dotenv
AUTH_EMAIL_VERIFICATION_ENABLED=1
AUTH_SMTP_HOST=smtp.your-provider.example
AUTH_SMTP_PORT=465
AUTH_SMTP_USER=your-smtp-login
AUTH_SMTP_PASSWORD=your-private-smtp-authorization-password
AUTH_SMTP_FROM=sender@your-domain.example
```

只支持 465 TLS 或 587 STARTTLS，验证证书且不允许明文降级。连接、认证检查使用：

```powershell
npm run auth:mail:check
```

开关为 0 时，检查工具只报告“邮箱功能已关闭”，不连接服务器。开关为 1 时，检查工具连接发信服务并验证登录，不发送邮件，不证明真实收件成功。检查通过后仍需在待上线环境完成一次真实注册和邮箱找回，检查收件箱/垃圾邮件及发送服务日志，记录实际送达结果。启用但服务未配置或发送失败时，接口明确返回 503，不提供控制台验证码或启用状态下的免验证后门。

发信服务配置必须与 Web/服务端升级一起完成，App 则需要发布包含新表单的版本。现有 APK 未因此自动更新，不应把本地浏览器通过等同于手机真机或生产送达验收。

## 启用后的用户入口

- Web 登录弹窗和窄屏登录页：注册时填写邮箱并获取验证码；“忘记密码？”使用账号及此前绑定的邮箱。
- Web 设置 → 账号与安全：老账号输入当前密码、验证邮箱后绑定；也可输入当前密码修改密码。
- App 登录页：注册、忘记密码；均要求确认新密码，登录仍只输入一次密码。
- App 我的 → 账号与安全：绑定恢复邮箱、查看脱敏地址、修改密码。
- 小程序新账号表单也已补充邮箱验证码字段，并补了找回密码入口；本次有代码检查，未做微信真机验收。

邮箱绑定后暂不提供自助换绑，避免仅凭已泄露密码替换恢复渠道；需要更换时由管理员核验处理。

## 重复注册与防刷

邮箱关闭期间仍保留账号名去重、IP 注册限流和管理员权限保护；邮箱去重及邮箱身份验证仅在开启后生效，不能声称关闭邮箱验证仍能防止同一个人使用不同账号名注册。

- 一个已验证邮箱绑定一个账号。邮箱地址大小写归一，Gmail/Googlemail 的点号及 `+` 别名归并。其他服务商可能存在无法识别的多邮箱/别名，不能据此宣称同一自然人绝不可能注册多个账号。
- 账号名按大小写不敏感检查重复，并有数据库插入触发器防并发绕过。既有大小写碰撞账号不合并、不删除，登录优先精确匹配；无精确匹配且唯一时才忽略大小写匹配。
- 新公开注册不会授予管理员权限，重启也不会将首个普通账号自动升级为管理员。保留已有管理员和明确配置的管理员；`ADMIN_USERNAME` 的保留名称不可被公开注册占用。
- 邮件验证码 6 位、10 分钟过期、最多 5 次尝试，按用途、账号、邮箱及密码版本绑定。成功使用即失效，重发使同范围旧码失效，数据库不保存明文验证码。
- 发送限制：同一邮箱跨用途/跨账号共享 60 秒间隔，每小时最多 5 封；同一地址每小时 20 封；全站每天 500 封。发送限制及登录/注册限流均保存在 SQLite；需要调整容量时应同时审查发信额度和滥用风险。
- 默认拒绝若干常见临时邮箱域及其子域，可用 `AUTH_BLOCKED_EMAIL_DOMAINS` 配置。名单不能覆盖全部临时邮箱，不把它当作完整的身份核验。
- 找回请求对未知账号、未绑定和已绑定情况返回相同结果并经过同一发信路径；只有历史绑定匹配且有效的账号能完成改密。邮件里有验证码也不代表它能重置任何指定账号。

## 未绑定邮箱且已忘记密码的老账号

账号名或新提供的邮箱不能证明原账号归属。管理员应先通过独立、可信渠道核验，不自动替用户绑定邮箱。服务器管理员可在**交互终端**运行：

```powershell
node server/account-recovery.js --username 原账号名
```

工具先要求确认已核验归属并填写简要工单号，再两次输入新密码，密码不回显、不放命令参数。它只修改指定账号密码、撤销旧登录/未用的恢复验证码并写入操作记录；不更改封禁状态、会员、证书或学习记录。恢复后让用户登录，自己绑定邮箱并再次修改密码。此工具没有 HTTP 路由，不向普通用户开放。未在真实用户数据库运行过。

## 数据、接口与验证

新增 `account_emails`、`account_email_codes`、`account_security_limits`；人工恢复时新增 `account_recovery_audit`。升级前备份完整 SQLite 数据库及其 WAL 状态，保留所有学习与会员表。回退旧代码时不要删除这些新增表或凭据记录；回退也会丢失新注册验证能力，需要单独评估。

公开接口：`GET /api/auth/security-config`、`POST /api/auth/email-code`、`POST /api/auth/reset-password`，以及原有普通/微信注册。

登录后接口：`GET /api/auth/security`、`POST /api/auth/bind-email`、`POST /api/auth/change-password`。所有响应继承 `no-store`，服务端保护发信凭据。改密/重置在同一数据库事务中更新密码、使所有旧会话及未用恢复码失效，不自动替用户登录。
