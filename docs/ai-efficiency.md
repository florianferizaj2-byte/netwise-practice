# AI 答疑与后端效率

本轮优化沿用 Express、SQLite、Zod 和现有 AI 网关，范围是老师答疑及请求记录查询。没有更换模型、价格、判分标准或教学内容。

## 减少重复输入

互动课原来同时发送 `lesson` 和 `reference`，其中 `reference` 是同一份卡片序列化后截取的前 3000 个字符。现在只发送本步已审核的 `lesson`，避免重复序列化和重复输入。保留知识点范围、学生基础、当前阶段和最近三轮有效问答，支持连续追问。

普通精讲的 `reference` 可能是独立参考资料，继续保留。未提交练习仍隐藏私有答案、参考资料和问答历史；所有返回内容仍经过严格 JSON、安全校验，互动答疑仍有独立支持性复核。

## 限制短答输出

- 老师短答默认上限由 2048 调整到 768 token；回答仍限制在 420 个中文字符以内。
- 仅在明确截断时允许扩大到 1024 token，最多两次尝试；原来扩大到 4096。
- 互动答疑复核上限由 700 调整到 384 token。
- 完整课程生成、内容审核与判分预算保持各自的现有规则。

这些数值是输出上限，不等于实际收费量或节省比例。实际输入、输出、缓存命中和失败调用继续记录到账号用量；没有匹配价格的费用显示未知。本轮用本地模拟模型验证，没有消耗真实模型额度，也没有测量线上 token 节省率。

## 数据库查询

老师的每日额度检查使用 `(user_id, day)` 部分索引，仅包含正在处理及已完成记录；过期处理中的请求使用 `lease_until` 部分索引回收。历史列表只读取所需 `data` 列，保留账号、课程与状态隔离。索引在初始化时增量创建，现有记录继续保留。

## 验证与维护

- `test/study-ai-security.test.js`：输出预算、截断恢复、上下文去重、防提示词攻击与未答题的答案隔离。
- `test/tutor-teacher.test.js`：真实本地 HTTP 网关、独立复核、并发请求、额度、失败重试、恢复及用量记录。
- `test/study-store-efficiency.test.js`：SQLite 查询计划实际采用额度与过期请求索引，历史问答隔离和顺序保持正确。

单独运行答疑集成测试时，需要在测试进程内生成临时 `AI_MASTER_KEY`，不使用生产密钥。Web 验收脚本已经创建隔离环境。后续应根据真实用量和响应质量继续调整预算；不能仅因模型兼容 Chat Completions 就向它发送其他厂商的专用参数。
