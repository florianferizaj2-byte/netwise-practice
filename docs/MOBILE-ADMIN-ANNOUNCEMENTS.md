# 手机端管理中心与公告

管理员登录考匠后，从“我的” → “管理中心”进入。普通账号与预览模式不显示入口，服务器会独立检查每次管理请求的管理员权限。

## 账号管理

支持搜索账号名或社区昵称、查看注册时间、账号 ID、当前题库、会员等级/到期时间和封禁状态。列表每页 30 条，可筛选正常/封禁账号并加载更多。

进入账号详情后，可以调整社区昵称、考试题库、会员等级和会员到期日期。昵称留空使用账号名；会员日期按北京时间当天结束计算，留空表示长期有效。选择“普通账号”会取消当前会员权益。点击“保存账号设置”后写入现有账号数据库，保留学习记录和会员额度的原有计算规则。

封禁/解封使用原管理接口。封禁前需要确认，封禁会立即撤销该账号的登录会话；不能封禁当前管理员或其他管理员。这个界面不修改登录账号名、密码、管理员角色或作者 API 凭据。

读取和保存之间如果账号已被其他管理操作修改，会提示重新读取，避免覆盖新状态。管理数据只在当前页面使用，不进入普通学习内容缓存；自己的资料更新会同步现有会话缓存，其他账号重新读取资料或登录后看到新设置。

## 公告热调整

“管理中心” → “公告管理”，编辑标题、正文和“在首页显示公告”，点击“保存公告”。保存后服务器立即返回新内容，无需重新编译或安装 App。

首页只显示一条简洁公告栏，点击查看全文。打开/返回首页或下拉刷新时拉取最新公告；首页在前台时每 60 秒检查一次。断网、请求失败或公告格式错误时保留上次有效内容；服务端关闭公告后，隐藏状态也会缓存。没有有效缓存时使用“暂无新公告”的内置占位。

公告为纯文本，支持换行；标题最多 80 字符、正文最多 8000 字符。不是应用代码更新渠道，不执行 HTML、脚本或远程操作。保存时校验读取版本，两个管理员同时编辑会收到冲突提示，可重新读取再保存。

公告默认保存在当前 DATA_DIR 的 mobile-announcement.json，例如 data/mobile-announcement.json，与账号数据库一起备份。首次启动时从 server/mobile-announcement.json 初始化；后续更新不覆盖已保存的公告。可通过 MOBILE_ANNOUNCEMENT_FILE 指定独立位置，建议使用绝对路径。更换路径或部署时应保留原公告文件。

直接编辑运行中的公告文件也会在下一次请求生效；建议优先使用手机管理页面，它会验证格式并原子替换文件。编辑源码中的初始模板不会覆盖现有数据文件。

## 服务接口

- GET /api/mobile/announcement：公开读取，禁止 HTTP 缓存，不需要账号凭据。
- GET /api/admin/mobile/users：管理员分页/搜索/筛选账号。
- GET /api/admin/mobile/users/:id：管理员读取账号详情与修改版本。
- PUT /api/admin/mobile/users/:id：管理员保存昵称、题库和会员设置。
- PUT /api/admin/users/:id/ban：沿用原有封禁/解封接口。
- GET /api/admin/mobile/announcement：读取公告与修改版本。
- PUT /api/admin/mobile/announcement：保存或隐藏公告。

所有管理接口均使用现有 Bearer 会话、管理员权限、无缓存响应与审计记录；不返回密码散列、盐、会话令牌或 API 密钥。

## 本地验证与部署范围

本次是 v0.4.5 本机验证版。账号和公告端到端检查使用独立临时数据库、临时文件和本地服务，不修改线上用户或公告。APK 沿用生产 API 地址，因此上线使用管理中心前，需要同步部署这次后端代码和初始模板；已存在的 DATA_DIR 数据与公告文件应保留。网站 /app/ 还需部署本次移动网页构建。

运行 node --test test/mobile-admin.test.js test/mobile-announcement.test.js 可检查权限、数据保存、分页、缓存和并发修改；先运行 npm run build:mobile-web，再运行 node test/mobile-admin.e2e.js 与 node test/mobile-announcement.e2e.js，可在 Chromium/WebKit 检查实际界面。

安卓系统悬浮窗、锁屏、省电策略和覆盖安装需要手机另行验收。定位模块仍离线运行，公告/账号管理不会上传定位坐标。
