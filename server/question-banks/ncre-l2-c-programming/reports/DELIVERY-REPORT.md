## 5. 题型调整

官方 2025 年版大纲第 3 页「考试方式」规定：单项选择题 40 分（含公共基础知识 10 分）、操作题 60 分，**客观题部分不含多项选择题与判断题**。

据此**删除全部 57 道非单选题**：多项选择 31 道、判断 26 道。删除记录（含全部被删题目正文、删除原因、时间戳）保存于 [removed-non-single-choice.json](removed-non-single-choice.json)，可审计、可恢复；相应知识点已由新编写的单项选择题覆盖。

同时更新题库说明与 `defaults.sourceVerification`，明确写出「题型与官方客观题部分保持一致，仅含单项选择题；官方另设操作题 60 分，不在本站客观题范围内」；并核实 `guide.json` 未出现多选/判断的题型表述。

## 6. 质量控制过程与已修复缺陷

### 6.1 盲审机制

每批题目在**冻结内容**后计算摘要，切分为两个半包，交由**两位相互独立的复核者**在不接触答案与解析的前提下独立作答；第二阶段再做解析与来源的对照核验。任何内容改动都会变更摘要，因此**必须重新盲审**——本次多处修订均按此重走了一遍完整复核。

### 6.2 复核者发现并已修复的实质缺陷

**技术表述类**

| 题目 | 缺陷 | 处理 |
|---|---|---|
| `op-002` | 把「结合方向从右到左」当作 `a *= b + 3` 等价形式的原因，混淆了**结合性**与**优先级** | 改写题干为按优先级解释 |
| `op-002` 选项 B | `a = a*b + a*3` 在整数语义下与正确项**恒等**（分配律），出现双解 | 换成无恒等关系的选项 |
| `io-003` | 把 `scanf` 格式串中的空格当成「必须原样输入」；实为空白指示符，可匹配 0 个或多个空白 | 改写解析，承认 `x=3y=4` 同样成立 |
| `stmt-004` | 解析称「右花括号后不能再加分号」，过于绝对（多写的只是空语句） | 改为「并不要求，错在『必须』」 |
| `array-2d-init-001` | 解析称补零「在具有静态存储期时才是确定的」，不准确（带初始化列表的聚合一律补零，与存储期无关） | 改写解析 |
| `stack-queue-001` | 干扰项归因与题面数据冲突（`5−2` 恰好等于正确答案），且一项无错因 | 按本题真正会算错的方式逐项重写 |
| `nested-count-001` | 对「输出 6」的归因算不出 6（按原说法得 4） | 改为可复算的归因 |

**干扰项数值类**（复核者**穷举验证**后判定无法由任何单一误解导出）

| 题目 | 原值 | 新值 |
|---|---|---|
| `rec-001` | 24（且旧解析自相矛盾地把 `g(4)` 同时当成 8 与 16） | **17** |
| `arr1-004` | 32 | **21** |
| `pointer-array-001` | 10（在给定的 4 字节前提下 4×5=20≠10） | **4** |

**答案与归类类**

| 题目 | 问题 | 处理 |
|---|---|---|
| `stmt-006` | 复核者答 C、答案键为 A。独立推导确认块内**只声明了 y**，`x = y*2` 修改的是**外层 x** → 答案键 A（`8,8`）正确 | 另找复核者独立确认 A；**未采纳错误意见** |
| `ptr-005` | 标为「指针作函数参数」，但形参是普通整型、程序中根本没有指针 | 改为真正的指针参数版本，保留原陷阱（只交换形参指针副本、未解引用），复核者确认归类正确 |
| `expr-002` | 选项「输出结果不确定」误导（结果完全确定），且知识点归「表达式与求值规则」不贴切 | 换掉该选项；知识点改归「类型转换」 |
| `expr-002` | 换选项后解析残留提到已不存在的「不确定」选项 | 清理解析 |
| `rec-001/002/003` | 复核者质疑知识点归口 | 提供目录定义后由独立复核者重新判定，确认归口**正确** |
| `pub-linear-001` | 插入平均移动次数存在两种教材口径（`n/2` 与 `(n+1)/2`），题干未定义位置如何计 | 题干写明「共有 n+1 个可插入位置（含表尾之后）」 |

**来源口径类**

| 题目 | 问题 | 处理 |
|---|---|---|
| `arr2d-001` | 题干锁定 VC++ 2010，所引来源却是 msvc-170（VS 2022）页面，无版本锚点 | 把「int 占 4 字节」写进题干，使答案自足，不再依赖外部实现文档 |
| `pointer-array-001` | 追加的来源实为整数类型表，**没有任何指针类型行**（复核者读原文抓出） | 改为把「32 位下指针与 int 各 4 字节」写进题干 |

### 6.3 生产过程中发现并修复的流程缺陷

1. **快照过期**：修改题目后只重新生成了一半的对照材料，导致交给复核者的快照是「旧题干 + 新解析」。复核者直接指出该错配。已补做并**新增快照一致性检查脚本**（逐题比对题干/选项/答案/解析）。
2. **合并脚本被整条覆盖**：第二阶段的对照核验记录只带 `checks`、不带 `independentAnswer`，原合并逻辑会把盲答结果冲掉。已改为**按字段合并**。
3. **合并顺序按文件名排序会出错**：修订轮次的文件名与字母序不一致，导致过期结论反过来覆盖最新结论。已改为**按文件修改时间排序**。
4. **产物命名兼容**：早期批次把整批盲答放在单个 `blind-review-result.json`，后续批次按半包/轮次存放，原过滤规则漏掉前者。已兼容两种命名。
5. **查重「自己撞自己」**：查重会把批次题目与已入库的同 id 副本比对，题目一经修订即报 `id_collision`。已补充**题库正文与来源同步**脚本，保证题库不留旧口径文本。
6. **摘要绑定整个来源清单**：`reviewDigest` 绑定题目 + provenance + **整个 sources 列表**，因此**新增任何来源都会让全批摘要失效**，必须在改来源后重跑 `hash`。这一点此前未意识到，已修正流程。

## 7. 已知限制与未做事项

1. **未做编译实证**：本环境不存在任何 C 编译器（`gcc`/`cl`/`clang`/`tcc` 均无）。所有程序跟踪题的答案由**手工逐轮推导 + 独立复核者另行重算**双路交叉得出，但**没有用编译器实际运行验证过**。
2. **部署与浏览器端验证未执行**：`verification.json` 中 `deploymentVerified` 与 `tutorBrowserVerified` 均为 `false`。本次目标不包含部署，我也未启动或替换任何服务。
3. **31 道公共基础题依赖豁免口径**：见 4.3。若要求更严（连定义性共识也须引技术文档），需另补一份软件工程／数据结构类的标准来源。
4. **`npm run build` 的阻塞由并发任务解决，非本次修复**：该关卡此前连续多轮失败于 `src/features/blue-exam.css` 缺失（该文件从未进入版本库）。复查时该文件已由并发任务补齐，随后我实际跑通了 build。我**没有**替它编造该文件。
5. **`guide.json` 与 `manifest.json` 的部分顶层字段未设**：`manifest.json` 的 `certificate` 下只有 `id/name/shortName/description/order`，没有单独的 `examVersion` 或 `updatedAt` 字段（本报告未报告不存在的字段）。
6. 本报告只覆盖 `ncre-l2-c-programming` 证书；仓库中其它证书与并发任务的改动未纳入。
